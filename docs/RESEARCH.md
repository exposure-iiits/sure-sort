# Source research — 17 October 2026

Phase 4 uses project-owned C++ parameter/curve/geometry code and existing Qt/LibRaw facilities. Preview tone work is bounded separately from decoding/output; crop and rotation are display transforms, with full-quality processing at output. Sorted-output refresh adds predecessor ownership and prepared replacement journaling. Native recovery tests exposed creation-time changes when reusing a recently deleted filename, consistent with Microsoft's documented [file tunneling behavior](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltgettunneledname). Publication/recovery verifies the same file ID, last-write time, length and SHA-256 while allowing that creation-time change, then records the published identity. Full-identity same-handle deletion checks remain intact. No GPL reference application code or new image-processing dependency was introduced.

Phase 3 implementation decisions: the watermark extends the existing Qt image pipeline without new dependencies or copied reference code. One QPainter SourceOver renderer operates on a photo-relative rectangle for display and output. PNG assets are decoded once, normalized to premultiplied sRGB, shared immutably and versioned by the encoded PNG's SHA-256. SQLite stores actual bytes so queued output does not depend on mutable external logo paths. Size uses the logo's longest edge relative to the photo's shorter side, giving tall and wide logos the same maximum scale; padding uses the same denominator. Generated Qt tests and the overlay benchmark validate these project decisions. See [WATERMARK](WATERMARK.md) and [PERFORMANCE](PERFORMANCE.md).

All four repositories were shallow-cloned into the ignored `.reference/` directory. The loader/decoder sources below were read and initial research/design written before implementation; a final prefetch cross-check is noted below. These are architectural observations; no GPL application code is incorporated into PhotoCull.

PhotoCull will keep only two decode slots, one pending foreground request, one pending detail request, and a short prefetch list. GUI callbacks are queued; folder epochs and navigation generations make obsolete results harmless. Closing drains workers after the event loop, while folder changes cancel and logically detach old work without waiting on the GUI thread. Preview loading remains independent of future RAW export.

Final source cross-check after integration: qimgv's `qimgv/core.cpp::loadFileIndex` preloads immediate next/previous files. `qimgv/components/directorymodel.cpp::{unloadExcept,load,preload}` trims to current plus those neighbors and bypasses duplicate/cache hits. `qimgv/components/loader/loaderrunnable.h` confirms its QObject/QRunnable signal bridge. PhotoCull expands the neighborhood to four next/two previous while decoding only one prefetch at a time and retaining a strict byte budget.


## Phase 5 primary format references

- [LibRaw output parameters](https://www.libraw.org/docs/API-datastruct-eng.html): explicit sRGB transfer settings and auto-bright threshold; checked against the installed 0.21.4 API/source.
- [CIPA Exif specification](https://www.cipa.jp/std/documents/e/DC-X008-Translation-2019-E.pdf): APP1/TIFF layout, orientation, color space and image dimensions.
- [W3C PNG eXIf](https://www.w3.org/TR/png-3/#eXIf): TIFF payload and chunk/CRC structure. Metadata implementation is original bounded code, with no additional runtime library.
